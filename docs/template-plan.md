# 转为通用模版 · 计划

> 写于 2026-11-22。2026 年颁奖活动已经结束，要把这个项目改成**每年都能用**的模版：
> 每年换主题，奖项编辑、图片导出、电子书继续沿用。
> 这是计划，还没开始动手。每一步做完在这里打勾，并写进 `CHANGELOG.md`。

## 现状

- **已经通用的**：活动名称、名单、照片、导出设计、电子书设置、效果设置都存在 `data/`；
  所有路径集中在 `lib/env.js`（`DATA_DIR` 等），改起来不难。代码里写死的「2026」「表扬大会」只剩几处默认值。
- **绑死在今年的**：
  1. **金色主题**：金色写死在约 15 个文件、90 多处（`display.css`、`control.css`、`guest.css`、`js/fx/*`、`ebook.js`、`record.js` 等）。
  2. **资料只有一份**：`data/` 就是「今年」，明年一改，今年的就被盖掉。

## 原则

- 每一步做完，**用今年的资料跑一遍，输出要和 1.62 完全一样**（大屏截图、导出图片、电子书逐像素对比）。
- 防泄露规则不变（`publicView()`、`/media/photo` 的检查）。
- 旧的 `data/` 结构要能自动接上（第一次启动时搬家，不丢资料）。
- 每步一个版本，分开提交，出问题能退回。

- [ ] 维护者自己把 `data/`、`Result/`、`config.json` 整份备份到别处（含名单和照片，不进 git）。

## 第 1 步：每届一个文件夹（2.0）

**目标**：往年的资料留着，新的一届从干净的状态开始。

- [ ] 文件夹：`data/events/<届名>/`（例：`data/events/2026/`），里面是现在 `data/` 的全部内容
      （`awards.json|enc`、`state.json`、`photos/`、`export-style.json`、`ebook.json`、`societies.json`、`fx.json`、`logo.png`、`material/`）。
- [ ] `data/current.json` 记录现在用哪一届。`data/fonts/` 继续放在外面，所有届共用。
- [ ] `lib/env.js` 的路径改成跟着「当前届」走；其它代码不用改。
- [ ] 旧结构自动搬家：启动时发现 `data/awards.json` 在旧位置 → 搬进 `data/events/2026/`，命令窗口显示一行提示。
- [ ] 控制端顶栏加「当前届」下拉：切换、新建、改名。
- [ ] 不是当前届的 = **只读存档**：可以看、导出图片 / 电子书 / Excel，不能改名单、不能开始现场。
- [ ] 「新建一届」时勾选要从哪一届带过来什么：

  | 可以带过来 | 一律不带 |
  |---|---|
  | 奖项结构（大类 / 分类 / 奖项名、揭晓方式，**清空得奖者**） | 名单（名字、班级、学号） |
  | 图片导出设计、素材图片 | 照片 |
  | 电子书版式（前言、编委可选） | 现场进度 |
  | 效果设置、学会对照表、Logo | |

- [ ] `.gitignore`：`data/events/` 整个不进 git。
- [ ] 测试：用合成资料建两届，确认切换后大屏、导出只用当前届；存档届的写入接口被拒绝。

## 第 2 步：主题独立出来（2.1 ~ 2.3，分三次做）

**目标**：换主题 = 在控制端选一个、微调颜色，不用改代码。

- [ ] **2.1 颜色变量化**：把写死的金色换成 CSS 变量（`--c-main`、`--c-main-2`、`--c-bg` 等），
      JS 特效改读 `FXC` 里的颜色。今年的样子保存成主题「金色 · 2026」，**默认输出必须和 1.62 一样**。
- [ ] **2.2 主题文件**：`data/events/<届>/theme.json`：主色、辅色、背景色、待机特效（星系 / 光河）、默认中英文字体、电子书底色和装饰色。
      控制端「效果控制」旁边加「主题」页：选择、微调、即时预览。
- [ ] **2.3 导出 / 导入主题**：主题保存成一个文件（不含名单），可以拿到别的电脑、别的年份用。
      `themes/` 放几个内置主题（金色、银蓝、红色……）。
- [ ] 电子书、图片导出、导出影片三处的颜色跟着主题走（这三处是 canvas 画的，要逐一改）。
