# 转为通用模版 · 计划

> 写于 2026-11-22。2026 年颁奖活动已经结束，要把这个项目改成**每年都能用**的模版：
> 每年换主题，奖项编辑、图片导出、电子书继续沿用。
> 这是计划，还没开始动手。每一步做完在这里打勾，并写进 `CHANGELOG.md`。

## 现状

- **已经通用的**：活动名称、名单、照片、导出设计、电子书设置、效果设置都存在 `data/`；
  所有路径集中在 `lib/env.js`（`DATA_DIR` 等），改起来不难。代码里写死的「2026」「表扬大会」只剩几处默认值。
- **绑死在今年的**：
  1. **金色主题**：金色写死在约 15 个文件、90 多处（`display.css`、`control.css`、`guest.css`、`js/fx/*`、`ebook.js`、`record.js` 等）。
  2. **资料只有一份**：`data/` 就是「今年」。决定：每年从空的 `data/` 重新开始，旧的由维护者自己备份（见第 1 步）。

## 原则

- 每一步做完，**用今年的资料跑一遍，输出要和 1.62 完全一样**（大屏截图、导出图片、电子书逐像素对比）。
- 防泄露规则不变（`publicView()`、`/media/photo` 的检查）。
- `data/` 的文件格式不改：往年备份的 `data/` 放回来照样能打开。
- 每步一个版本，分开提交，出问题能退回。

## 第 1 步：每年从空的 `data/` 开始

**维护者定（2026-11-22）**：做法很简单，每年都重新开始，`data/` 默认为空。不做「每届一个文件夹」、不做存档切换。

- [x] `data/` 整个不进 git，没有例外（原本放行的 `data/export-style.json`、`data/fx.json`、`data/fonts/` 也移出 git；
      维护者选「直接丢掉」：明年回到程序的默认值重新调，2026 的设计只留在 `v1.62-2026` tag 和维护者自己的备份里）。
- [x] 空的 `data/` 第一次启动：照现在的做法自动建文件夹、生成示例名单（维护者选，方便老师先试操作）。
- [x] 已确认 `server.js` 启动时会自动建 `data/`、`photos/`、`_cache/`、`fonts/`、`logs/`。
- [ ] **新的一年怎么开始**（维护者自己手动做，程序不做删除动作）：
  1. 关掉程序；
  2. 把整个 `data/`（和 `Result/`）搬到备份的地方，或改名成 `data-2026/`；
  3. 重新启动 → 程序自动建一个新的空 `data/`；
  4. 在控制端导入新的 Excel 名单、上传照片、调图片导出设计和电子书。
- [ ] 想沿用去年的某样设置时：从备份里把那一个文件抄回 `data/`（例：`export-style.json`、`fx.json`、`societies.json`、`logo.png`、`fonts/`）。

⚠ **渲染服务器**：`git pull` 这次改动时，Git 会把服务器上的 `data/export-style.json`、`data/fx.json`、`data/fonts/` 删掉
（因为它们从 git 里移除了）。`pull` 之前先在服务器上备份这几个文件，`pull` 完再抄回去。
