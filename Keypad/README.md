# 实体按键（Keypad）

这个文件夹放所有和实体按键有关的东西：

| 文件 | 用途 |
|---|---|
| `pico-guest-button/` | **嘉宾实体揭晓按钮 · Pico 测试版**：普通 Pico 没有 WiFi，插 USB 到一台电脑，由电脑上的小程序代它连服务端 |
| `esp32-guest-button/` | **嘉宾实体揭晓按钮 · ESP32 正式版（灯版）**：ESP32 自己连 WiFi，不用电脑；用灯 / 三色灯显示情况 |
| `esp32-guest-button-lcd/` | **ESP32 屏幕版**：和灯版一样，改用一块 1602A 屏幕直接用文字显示情况（见下面「ESP32 屏幕版」） |
| `test-protocol.js` | 两个版本都没有时，用电脑模拟按钮发请求，检查服务端回应 |
| `code.py` | 原本的 9 键 USB MIDI 键盘（Pico + CircuitPython，给 MA2 灯光台用），和颁奖系统无关 |

建议的顺序：先用 **Pico 版**测试（现成的 9 键键盘就能用），流程确认没问题后，再换 **ESP32 版**正式上场。两个版本的按法和灯号完全一样。

## 它做什么

按钮等于一部「嘉宾手机」：

1. 主持人在控制端按「🎤 交给嘉宾揭晓当前奖项」（或 `G`）→ 按钮的**灯常亮**。
2. 嘉宾**按一下**按钮 = 揭晓（和手机上按住金色按钮一样；逐一揭晓的奖项每按一次出一位）。
3. 揭晓完、换奖项或主持人收回授权时，灯自动熄灭，按了也没有作用。

控制端「嘉宾揭晓」下面会显示连上的按钮：ESP32 版每个按钮一行，有板子编号、IP、**WiFi 信号强度和延迟**（见下面「控制端看到的按钮情况」）；Pico 版显示在「嘉宾手机」那一行（显示电脑的 IP）。手机和按钮可以同时用；服务端 1 秒内只算一次，两边同时按不会连跳两位。

防泄露不受影响：按钮只收到和嘉宾手机一样的「已揭晓」资料，而且只看其中「能不能按」这一项。

### 灯号（两个版本一样）

| 灯 | 意思 |
|---|---|
| 快闪 | 正在连服务端（Pico 版：也可能是电脑上的 bridge 没开） |
| 慢闪（亮 1 秒、灭 1 秒） | 只有 ESP32 版：设置模式，或连不上 WiFi，设置网页已打开（见下面「用手机改设置」） |
| 灭 | 已连上，等主持人授权 |
| **常亮** | **可以按** |
| 闪 3 下 | 刚揭晓成功 |
| 短闪 1 下 | 按了但没有授权、按太快，或还没连上 |
| 闪 2 下、停一下（重复） | 嘉宾链接错误：密钥不对（可能按过「更换嘉宾链接」），或链接写错 |

## Pico 测试版（`pico-guest-button/`）

```
[按钮 + 灯] ── Pico ──USB── 电脑（bridge.js）──WiFi / 网线── 颁奖服务端
```

### 接线

默认用**原本 9 键键盘的第 1 个键（MA，GP18）和它的灯（GP1）**，不用重新接线。

自己做单键盒的话：按钮一脚接 GP18、另一脚接 GND；灯 = GP1 → 220Ω 电阻 → LED 长脚，LED 短脚接 GND。想用别的脚位：改 `code.py` 最上面的 `BUTTON_PIN`、`LED_PIN`。

### 第一次设置

1. **Pico**：把 `pico-guest-button/code.py` 复制到 CIRCUITPY 盘，覆盖原本的 `code.py`。
   - 原本的 MIDI 版在 `Keypad/code.py` 有一份，要改回 MIDI 键盘时复制回去就好。
   - 这个版本不需要 `adafruit_midi` 等额外的库。
   - Pico 里的 `boot.py` 平时会把 CIRCUITPY 盘藏起来；要让它出现，插 USB 时**同时按住 Up 和 Down 两个键**（GP10 + GP14）。
   - ⚠ 维护者的电脑上 CIRCUITPY 盘出现时是**写保护**（只能读），复制不进去（2026-10-19 发现，原因未查明，清除只读标记需要管理员权限）。当时的绕法：平常开机（盘藏起来）→ 经串口进 REPL → `storage.remount('/', readonly=False)` → 由 Pico 自己写入文件。
2. **电脑**（要装 Node.js 18 以上，和颁奖服务端可以是同一台，也可以是别台，只要在同一个网络）：
   - 把 `bridge-config.example.json` 复制一份，改名为 **`bridge-config.json`**，用记事本填「嘉宾链接」：控制端右侧「嘉宾揭晓」→「复制」得到的整条链接。
   - 「串口」一般保持 `"自动"`。找不到 Pico 时，到「设备管理器 → 端口」看它是 COM 几，改成例如 `"COM5"`。
3. Pico 插 USB，双击 **`start-bridge.bat`**。黑色窗口会显示连线情况和每次按键的结果。**关掉黑色窗口 = 按钮失效。**

### 注意

- 开着 Thonny、Mu 或其它串口监视器时，bridge 打不开串口（窗口会提示），先关掉它们。
- 改了 `code.py`，Pico 会自动重启，bridge 会自己重连，不用重开。
- `bridge-config.json` 含嘉宾密钥，已加进 `.gitignore`，不会进 git。

## ESP32 正式版（`esp32-guest-button/`）

```
[按钮 + 灯] ── ESP32 ──WiFi── 颁奖服务端
```

### 接线

| 零件 | 接法 |
|---|---|
| 按钮 | 一脚接 **GPIO 4**，另一脚接 **GND**（不用电阻）。四脚按钮要接**对角**的两只脚，接到同一边的两只脚会一直是「按下」 |
| 灯 | **GPIO 2** → 220Ω 电阻 → LED 长脚；LED 短脚接 **GND** |
| 三色灯（可选） | **红 GPIO 25**、**黄 GPIO 26**、**绿 GPIO 27**，每颗都是 GPIO → 220Ω 电阻 → LED 长脚，短脚接 GND |

- 很多 ESP32 开发板的 GPIO 2 上本来就有一颗蓝色板载灯，没接 LED 也能先测试。
- 三色灯和单灯可以同时用；没接哪一颗，就把 `.ino` 里的 `RED_PIN` / `YELLOW_PIN` / `GREEN_PIN` 改成 `-1`。

三色灯的意思（ESP32 版）：

| 灯 | 意思 |
|---|---|
| 🔴 红常亮 | 正在连 WiFi / 服务端 |
| 🟡 黄常亮 | 已连上，等主持人授权 |
| 🟢 绿常亮 | **可以按** |
| 🟢 绿闪 3 下 | 刚揭晓成功 |
| 🔴 红短闪 1 下 | 按了但没授权、按太快，或还没连上 |
| 🔴 红闪 2 下、停一下 | 嘉宾链接错误 |
| 🔴🟡 红黄轮流慢闪 | 设置模式（手机连 AwardButton-XXXX 改设置） |
| 🟡 黄快闪 | 开机时按着按钮：继续按住 3 秒进设置模式，放开 = 正常开机 |
- 想用别的脚位：改 `esp32-guest-button.ino` 最上面的 `BUTTON_PIN`、`LED_PIN`。避开 GPIO 0、12、15（开机用的脚位）。

### 第一次上传程序（只要做一次）

1. 安装 [Arduino IDE](https://www.arduino.cc/en/software)。
2. 「工具 → 开发板 → 开发板管理器」，搜 **esp32**，安装 Espressif Systems 的那一个。
3. 用 Arduino IDE 打开 `esp32-guest-button/esp32-guest-button.ino`，「工具 → 开发板」选你的型号（不确定就选 **ESP32 Dev Module**），选好端口，按「上传」。
4. 上传后灯会**慢闪**，表示进入设置模式，接着照下面「用手机改设置」做。

（可选）打开「工具 → 串口监视器」（波特率 115200），可以看到连线情况和每次按键的结果。

### 用手机改设置（WiFi、嘉宾链接）

设置存在 ESP32 里，断电不会丢；以后换 WiFi、换服务端电脑、按过「更换嘉宾链接」，都用手机改，**不用重新上传程序**。

1. 进入设置模式（灯慢闪），三种情况都会：
   - 第一次开机（还没设置过）；
   - **插电时按住按钮不放，灯快闪约 3 秒后放开**（不到 3 秒就放开 = 正常开机）；
   - 开机 60 秒还连不上 WiFi，会自动打开设置网页，同时继续试连 WiFi。
2. 手机连 WiFi **`AwardButton-XXXX`**，密码 **`award123`**（XXXX 是每块板子不同的编号）。
3. 手机一般会自动弹出设置页；没弹出就用浏览器打开 **http://192.168.4.1**（要打 `http://`，不是 `https://`）。
   - 用 Windows 电脑连热点时，会自动弹出 `https://www.msn.com/…?ocid=wispr`，那一页一定打不开（ESP32 不能做 HTTPS），直接在地址栏改成 `http://192.168.4.1` 就好。
4. 填好后按「保存并重启」：
   - **现场 WiFi**：可以从附近的 WiFi 里选，或直接输入名称。
   - **WiFi 密码**：留空 = 不改。换了一个 WiFi 却留空，就当作没有密码的 WiFi。
   - **嘉宾链接**：在控制端右侧「嘉宾揭晓」→「复制」，整条贴上。留空 = 不改。
5. 按钮重启后灯快闪，然后熄灭，就表示已经连上服务端。

- 网页上的嘉宾链接只显示密钥的后 4 位，不会露出整条。
- 设置热点只在设置模式或连不上 WiFi 时开着，连上 WiFi 就自动关掉。
- 想改热点密码：改 `.ino` 最上面的 `AP_PASS`（至少 8 位），再上传一次。

### 和服务端怎么同步

ESP32 版每 0.5 秒问服务端一次「现在能不能按」，灯号**以服务端的回答为准**：WiFi 闪断、服务端重启、按钮自己重开，连回来后马上就是正确的状态，不会出现「服务端已经收回授权，灯还亮着」。连续 3 次问不到（约 2 秒）就当作断线，灯回到「正在连服务端」，这时按了不算。

- 需要颁奖系统 **1.38 以上**。服务端太旧时，串口监视器会写「服务端版本太旧」，屏幕版显示 `Update server!`。
- 主持人授权后，灯最多晚 0.5 秒亮（想更快：改 `.ino` 的 `POLL_MS`，单位毫秒）。

### 控制端看到的按钮情况

控制端「嘉宾揭晓」下面，每个 ESP32 按钮一行，每 2 秒更新：

| 显示 | 意思 |
|---|---|
| `AwardButton-XXXX` + IP | 哪一块按钮（编号和设置热点的名称一样） |
| 信号 −55 dBm（好） | WiFi 信号：−60 以上**好**、−60 ~ −70 **一般**、−70 ~ −80 **弱**、−80 以下**很弱**（靠近路由器，或换个位置） |
| 延迟 12 ms（平均 15，最高 40） | 按钮问一次服务端来回要多久。一般几毫秒到几十毫秒；常常上百毫秒，表示 WiFi 很挤或信号差 |
| 开机以来问服务端失败 N 次 | 偶尔几次没关系；一直增加 = WiFi 不稳 |
| 红框「离线：N 秒前最后联系」 | 超过 3 秒没消息：按钮没电、WiFi 断了，或嘉宾链接已更换。这时灯不会亮，按了也没用 |

上线 / 离线会写进 `logs/audit.log`（`BUTTON+` / `BUTTON-`）。

### 注意

- **WiFi**：ESP32 只能连 **2.4 GHz、普通密码**的 WiFi。学校那种要输入帐号密码的 WiFi 连不上，现场请用自己的路由器或手机热点，和服务端电脑在同一个网络。
- `secrets.h` 不再需要。如果想在上传时就先写好默认值，可以照 `secrets.example.h` 做一份；它只在「还没用网页设置过」时有用。这个文件已加进 `.gitignore`，不会进 git。

## ESP32 屏幕版（`esp32-guest-button-lcd/`）

和灯版是**两个独立的文件**，按法、设置网页、手机设置步骤完全一样，只是把三色灯换成一块 **1602A 屏幕**（16 字 × 2 行）。上传方法同上，打开的是 `esp32-guest-button-lcd/esp32-guest-button-lcd.ino`。不用另外安装库。

- 设置和灯版存在同一个地方：同一块 ESP32 改烧另一个版本，WiFi 和嘉宾链接不用重新设置。
- 1602A 只能显示英文和数字，所以屏幕上是英文（中文意思见下表）。WiFi 名称有中文的话会显示成 `?`。

### 接线

默认是**直接接屏幕的 16 只脚**（并口，屏幕上从左到右印着 1~16）：

| 屏幕脚 | 名称 | 接到 |
|---|---|---|
| 1 | VSS | GND |
| 2 | VDD | **5V**（ESP32 板子上写 VIN 或 5V 的脚） |
| 3 | V0 | 对比度：10kΩ 电位器的中间脚（电位器两边接 5V 和 GND）。没有电位器：串一个约 1kΩ 电阻接 GND |
| 4 | RS | **GPIO 27** |
| 5 | RW | GND |
| 6 | E | **GPIO 14** |
| 7~10 | D0~D3 | 不接 |
| 11 | D4 | **GPIO 32** |
| 12 | D5 | **GPIO 33** |
| 13 | D6 | **GPIO 25** |
| 14 | D7 | **GPIO 26** |
| 15 | A（背光 +） | 5V，最好串一个 220Ω 电阻 |
| 16 | K（背光 −） | GND |

- 按钮照旧接 **GPIO 4** 和 GND；GPIO 2 的灯可接可不接（不用就把 `LED_PIN` 改成 `-1`）。
- **背光亮了但看不到字，或第一行全是方块**：对比度不对，转电位器；用电阻的话换大一点或小一点（几百 Ω ~ 2kΩ 之间试）。
- **有字但是乱码**：多半是 D4~D7 其中两条接反，或 RS / E 接错。
- RW 一定要接 GND：这样屏幕只收不送，5V 的屏幕不会把电压送回 ESP32。

屏幕背面焊了 **I2C 转接板**（只有 GND、VCC、SDA、SCL 4 只脚）的话：把 `.ino` 里的 `LCD_I2C` 改成 `true`，VCC 接 5V、SDA 接 GPIO 21、SCL 接 GPIO 22；地址自动找，对比度转转接板上的蓝色电位器。

### 屏幕上的字

| 屏幕 | 意思 |
|---|---|
| `Setup: join WiFi` / `AwardButton-XXXX` → `WiFi password:` → `Then open page:` / `192.168.4.1` | 设置模式，几页轮流显示：手机连哪个热点、密码、打开哪个网址 |
| `Can't join WiFi:` / WiFi 名称 | 连不上 WiFi，设置网页已自动打开 |
| `Phone connected` | 手机已打开设置网页 |
| `Hold 3s = setup` / `#####…` | 开机时按着按钮：进度条走满 = 进设置模式，提前放开 = 正常开机 |
| `Connecting WiFi` / WiFi 名称 | 正在连 WiFi。第 2 行会轮流显示连不上的原因：`Wrong password?` 密码不对、`WiFi not found` 找不到这个 WiFi（名称错 / 5 GHz / 太远）、`Signal too weak` 信号太弱 |
| `Finding server` / 服务端 IP | WiFi 已连上，正在连服务端。轮流出现 `Server offline?` = 连不上服务端：检查服务端有没有开、电脑 IP 有没有变 |
| `Bad guest link` | 嘉宾链接错误（密钥不对）：插电时按住按钮 3 秒，用手机贴上最新的链接 |
| `Waiting for host` | 已连上，等主持人授权；第 2 行轮流显示按钮自己的 IP |
| **`PRESS BUTTON`**（闪）/ `to reveal!` | **可以按** |
| `Revealing...` | 按到了，正在揭晓 |
| `REVEALED!` | 揭晓成功 |
| `Not allowed yet` | 主持人还没授权，这一下不算 |
| `Too fast` | 按太快，1 秒内只算一次 |
| `Not connected` | 还没连上服务端，这一下不算 |

## 两个版本都要注意

- **服务端电脑的 IP 变了**（换了路由器、重新开机拿到别的 IP）→ 要改链接（Pico 版改 `bridge-config.json` 后重开；ESP32 版插电时按住按钮 3 秒，用手机改）。建议在路由器上把服务端电脑的 IP 固定下来。
- **按过「更换嘉宾链接」** → 旧密钥失效，灯会变成「闪 2 下」，换成新链接（ESP32 版同样用手机改）。
- **怕嘉宾误触**：把按住时间改长——Pico 版 `code.py` 的 `HOLD_TIME = 0.5`（秒），ESP32 版 `.ino` 的 `HOLD_MS = 500`（毫秒）。默认是一按就揭晓。

## 没有按钮时测试

开一个测试服务端（不要用正式的 `data/`），然后任选一种：

```bat
:: 模拟 ESP32 的请求，自动跑完整流程（给控制端密码时会自动授权、按一下，并检查控制端看得到信号和延迟）
node Keypad\test-protocol.js "http://127.0.0.1:8097/guest?k=嘉宾密钥" 控制端密码

:: Pico 版的电脑端，不开串口：输入 KEY:DOWN 按 Enter = 按一下，屏幕会印出灯号
node Keypad\pico-guest-button\bridge.js --stdin
```
